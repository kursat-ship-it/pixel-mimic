# 像素風科普循環短片（追著一個微小的東西穿越尺度，最後變成一個日常比喻，首尾無縫循環）

## 辨識特徵（看參考影片的哪些東西會判斷成這個風格）
- 畫面：9:16 直式；180×320 像素格放大 ×6；深紫黑底＋單一琥珀色「能量」；球體／膠囊有偽 3D 明暗後再量化＋抖色；處處有漂浮塵粒與抖色光暈；沒有角色
- 剪接：幾乎是一鏡到底，靠連續推拉鏡「換尺度」（拉遠揭示更大的系統、推進穿過亮點）；硬切只有 2–3 次且都在拍點上；每個知識點 ≈ 8 拍（2 小節）
- 聲音：無旁白、純音樂（標題帶 🎧）；火花、閃光、跳躍都對齊音符
- 文字：頂部置中黑底方框、全大寫像素字、1–3 行、≤6 個字；數字那一行用琥珀色；約 0.1 秒抖色淡入淡出；每 8 拍一張字卡
- 結構：鉤子問題 → 5 個機制步驟 → 無字高潮（連鎖觸發＋尺度爆開）→ 大數字 → 日常比喻物件（品牌刻在物件上）→ 推回第一格無縫循環

## 製作預設
- 比例 / 長度 / fps：1080×1920、45–50 秒、60 fps 輸出（參考片；@hayret.piksel 頻道預設 30 fps，見 ../brand/BRAND.md）（像素動作 12 fps、鏡頭每格移動）；BPM 110–125，全部時間用拍寫
- 流程重點：
  - pixel-art 引擎要改成直式：LW×LH = 270×480 ×4（或 180×320 ×6 以完全對齊參考），studio.html canvas 與 render.mjs window-size 改 1080×1920
  - 連續變焦不可以縮放點陣圖：每格用世界座標×scale 重新畫幾何（disc/ball/line/ring），再量化到像素格
  - 字卡不用 say() 對話框：用 overlay 畫 pxText＋黑底方框（top ≈ 10% 畫面高、置中），數字行琥珀色，抖色淡入淡出 6 格
  - 色盤：自訂 regRamp（violet ramp ＋ amber ramp），不用 day/dusk/night
  - 最後 3–4 秒必須推回到第 0 秒的同一個畫面（含字卡重現），檢查首尾格差異

  - 本機已有獨立引擎 bitloop（bitloop/），直接吃 topic spec JSON 輸出 1080×1920 MP4，不需要 Chrome / Claude Code

## 已知的坑
- analyze.py 會把直式暗色畫面的上下暗部誤判為手機錄影 UI 而裁成 1080×488 → 分析這類參考片時要對全畫面另跑 scenedetect / 抽格
- 參考片是 AV1 編碼，OpenCV 無法解碼 → 先轉 H.264（ffmpeg -c:v libx264）再分析
- 硬切偵測只抓到 3 刀；真正的「段落」靠推拉鏡換景，要用 2 fps 總覽圖＋字卡出現時間來切段
- Press Start 2P 的土耳其文大寫附加符號字母（Ş Ğ Ü Ö Ç）被壓矮，字卡請用 bitloop 內建 5×7 字型
